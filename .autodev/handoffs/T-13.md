## Write-ahead: `PROMPT_VERSION` 5 → 6 invalidates every cached explanation on this machine

`src/interpret.ts#PROMPT_VERSION` is bumping from 5 to 6 in the very next commit, because
the interpret prompt itself is changing (it now asks for `alternatives` in the same call
that already writes `what`/`why`/`summary`). `stopKey()` folds `PROMPT_VERSION` into the
cache filename by design (`src/interpret.ts`'s own doc comment: "old cached answers were
produced by a different question"), so **every explanation this machine has ever paid for
under v5, sitting in `.cache/interpret/`, becomes unreachable the moment this lands** — not
deleted, just never looked up again under the new key. The next real (non-`--cached-only`)
interpret run on any repo this machine has already toured will look like a full
re-interpretation and re-spend the tokens. **That is by design, not a regression**: the v5
cache entries answered a different question (no alternatives asked), so serving them under
v6 would be dishonest. Anyone reading a cost spike after this ticket merges should check
`PROMPT_VERSION` first before assuming something broke.

At the time this note was written, this worktree's own `.cache/interpret/` did not exist
yet (verified: `find .cache -type f` — nothing), so THIS branch's own work created no such
spike locally. The risk is real on any machine (or CI cache) that already ran repo-tour's
`tour`/`serve` interpret stage under v5.
