## Write-ahead: `PROMPT_VERSION` 5 → 6 invalidates every cached explanation on this machine

`src/interpret.ts#PROMPT_VERSION` moved from 5 to 6 in this branch's second commit, because
the interpret prompt itself changed (it now asks for `alternatives` in the same call that
already writes `what`/`why`/`summary`). `stopKey()` folds `PROMPT_VERSION` into the cache
filename by design (`src/interpret.ts`'s own doc comment: "old cached answers were produced
by a different question"), so **every explanation any machine has ever paid for under v5,
sitting in `.cache/interpret/`, becomes unreachable the moment this merges** — not deleted,
just never looked up again under the new key. The next real (non-`--cached-only`) interpret
run on any repo that machine has already toured will look like a full re-interpretation and
re-spend the tokens. **That is by design, not a regression**: the v5 cache entries answered
a different question (no alternatives asked), so serving them under v6 would be dishonest.
Anyone reading a cost spike after this ticket merges should check `PROMPT_VERSION` first
before assuming something broke.

This worktree's own `.cache/interpret/` never held anything under v5 (verified empty before
this branch started, and confirmed still empty at close-out — every test in this ticket
either injects a canned `runner` into an isolated temp `cacheDir`, or drives the CLI with
`--cached-only`, which never writes to the cache at all), so this branch's own work created
no local cost spike. The risk is real only on a machine (or a CI cache) that already ran
repo-tour's `tour`/`serve` interpret stage under v5.

## What each piece does

- `src/interpret.ts` — `InterpretOptions.runner?: typeof runLlm`, defaulting to the real
  `runLlm`, threaded through both call sites (`interpretStops`, `interpretArchitecture`).
  `StopMeaning.alternatives: Array<{label, consequence}>`, asked for in the same call as
  `what`/`why`/`summary` via one new `SYSTEM` bullet and an updated JSON shape line.
  `parseAnswer`'s new `parseAlternatives` helper degrades a missing, malformed, or
  junk-padded field to `[]` rather than failing the whole answer. `PROMPT_VERSION` 5 → 6.
- `src/build/interpret.ts` (new) — `interpretPlan(plan, digest, opts)`. Builds the
  `CodeStep[]` `interpretStops` actually reads from a plan's own `symbol` steps (their
  ranges) and `file` steps (`1..min(loc, 120)`, deduplicated by `stepKey` against a
  same-range symbol — real on a tiny single-function file with no leading blank line, and
  otherwise a wasted second call for lines already explained). `shape` steps are skipped
  (refinement notes: `interpretArchitecture` writes one whole-system brief, not one per
  chapter). The fold (`foldMeaning`) is `authorOnlyDecision`'s inverse: the author's
  `id`/`label`/`taken` survive, its `consequence` is upgraded to the model's `summary`, the
  alternatives become new `taken: false` options with small step-local ids, `why` prefers
  the model's own and falls back to the pre-existing docstring/honest-fallback text, and
  `whySource` becomes `'interpret'`. A step nothing could interpret is returned completely
  unchanged. Returns `{ plan, cost }` — a NEW `BuildPlan` (never mutates the input, same
  doctrine as `buildPlan` itself), `cost` taken directly from `interpretStops`'s own
  `InterpretCost`, never `buildPlan`'s zeroed `provider: 'none'` sentinel.
- `src/ask.ts` — `AskContext.build?: { question, options: Array<{label, consequence,
  taken}>, why, learnerDiff? }`. `buildContextBlock` renders it under
  `--- THE BUILD STEP ---`, each option tagged `[author]`/`[alternative]`, `why` on its own
  line, and the learner's file against the author's (when there is one) clipped at 8,000
  characters via the same `clip()` the PR diff already uses. `ASK_PERSONA` untouched.
- `src/cli.ts` — `plan <path> [--json] [--interpret [--cached-only]]`. `--interpret` is a
  NEW `Args.planInterpret` field (default `false`), deliberately separate from the
  pre-existing `Args.interpret`/`--no-interpret` pair `tour`/`serve` already use (that pair
  defaults to `true` and means "skip the model"; `plan` needed the opposite default and
  polarity — reusing the same field would have made `repo-tour plan <path>` with no flags
  silently start interpreting). Reuses the existing `--provider`/`--model` args unchanged.
  Prints an honest cost line: `$0.0042`, or `"this provider does not report usage"` when
  `metered` is `false`.

## Testability without a model

Every test in this ticket injects a canned `InterpretOptions.runner` (or, for the CLI
tests, uses `--cached-only` against an empty cache) — none spawns the real `claude` CLI.
The "runner seam" test additionally defends against its own regression: it asserts the
EXACT canned text landed in `meanings`, so if the seam ever silently fell back to the real
`runLlm`, this test would either find an empty `meanings` map (no `claude` installed) or
mismatched content (a real reply, vanishingly unlikely to coincide with the canned text) —
discriminating either way, never a silent pass.

## Surprises / things worth knowing

1. **The locate doc and the plan doc disagreed slightly on `interpretPlan`'s return
   shape** — the locate doc gives `Promise<{ plan: BuildPlan; cost: InterpretCost }>`
   explicitly; the plan's prose ("Returns a NEW `BuildPlan` with `cost = result.cost`")
   reads either way in isolation. Resolved in favor of the locate doc's literal signature,
   because it keeps `interpretPlan` consistent with the OTHER two functions in the
   "interpret" family: `interpretStops` returns `{meanings, cost}`, `interpretArchitecture`
   returns `{meaning, cost}`. `interpretPlan` returning `{plan, cost}` completes the
   pattern; the returned `plan`'s own `.cost` field is set to that same `cost` value either
   way, so no information is lost under either reading.
2. **`quiet` was dead code in `src/cli.ts`** before this ticket (`const quiet =
   args.command === 'tour';`, declared but never read anywhere). The plan's own text for
   the `plan` verb's `onProgress` wiring reads `quiet ? undefined : console.error`. Since
   `plan`'s own code path runs and returns BEFORE that declaration (it sat physically below
   the `plan` block), the declaration was moved up to right after `const m =
   result.manifest;` so `plan` can read it too — for `plan` specifically, `quiet` is always
   `false` (`plan !== 'tour'`), so `--interpret`'s progress messages always print to
   stderr, which is a reasonable default for the one stage that spends money either way.
3. **Two conflicting conventions for the CLI's new interpret flag.** `--no-interpret`
   already existed (default `true`, meaning "interpret unless told not to", used by
   `tour`/`serve`). `plan --interpret` needed the OPPOSITE default and polarity ("stay free
   unless asked to interpret"). Reusing the same `Args.interpret` field for both would have
   made bare `repo-tour plan <path>` silently start spending tokens by default — kept them
   as two separate fields (`interpret` and the new `planInterpret`) instead.
4. **Widening `StopMeaning` rippled into `test/pipeline.test.ts`'s pre-existing fixtures.**
   Ten `StopMeaning`-shaped object literals there (feeding `applyMeanings`/`fileDelta` in
   T-5's own tests) predate `alternatives` and don't strictly satisfy the interface anymore
   — invisible to `npm run typecheck` (`tsconfig.json` excludes `test/`) and to `npm test`
   (neither consuming function reads `.alternatives`, so nothing breaks at runtime), but a
   real type-consistency gap all the same. Verified this both ways: an ad-hoc `tsc --noEmit`
   run that INCLUDES `test/` (a scratch tsconfig, not committed) surfaced exactly these ten
   sites plus several unrelated pre-existing `PrRefs`/`source.head` looseness errors that
   were confirmed (via `git stash`) to predate this ticket entirely. Fixed the ten that are
   this ticket's own doing; left the pre-existing, unrelated ones alone.
5. **A same-range collision between a file step and its own sole symbol is real but rare**
   — a tiny single-function file with no leading blank line/import has its file-head range
   (`1..min(loc,120)`) coincide exactly with that one symbol's full span. `codeStepsFor`
   dedupes by `stepKey` before ever building the request, so this costs one call instead of
   two; the fold step recomputes each step's own range independently and looks it up
   fresh, so both steps still correctly receive the (shared, and in this case genuinely
   identical) meaning rather than one of them silently missing out.
