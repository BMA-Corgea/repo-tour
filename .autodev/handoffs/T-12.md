## What I'm about to try (write-ahead, per the plan's own risk note)

Plan step 3a: chapters come from `buildArchitecture(digest)` when it yields >= 2 parts
(bottom-up: `arch.layers` is entry-points-first/foundations-last by construction, so the
build order is that list reversed and flattened, ties broken by subsystem score desc then
path). When architecture collapses to < 2 parts, fall back to `digest.tiers.filter(t =>
t.kind === 'subsystem')` as the chapter list directly (AC1's original, pre-refinement
wording), using a locally-computed edge rollup + the same bottom-up peel — NOT
`buildArchitecture`'s internals, which are exactly what collapsed.

Concretely, I'm about to write one generic, module-private helper in `plan.ts`:

```
dependencyOrder(nodes, edgesWithinTheSet, tiebreak): T[]
```

— Kahn's algorithm where a node is placeable once every node it points TO is already
placed (dependencies first). This one function serves BOTH chapter ordering (nodes =
chapter paths, edges = subsystem/tier import rollup) AND file ordering within a chapter
(nodes = file paths, edges = the import graph restricted to that chapter) — the same
"leaves first" rule at two granularities, per spec §4.1's table.

**The specific risk the plan calls out:** a small fixture may make `buildArchitecture`
yield a single part (or zero), so the tier-fallback branch needs its OWN dedicated test,
not an assumption that the primary path's logic degrades gracefully into it. My plan for
that test: two sibling top-level directories, each with exactly ONE direct code file (so
`chooseSubsystems`'s `directCode(t) >= 2` filter excludes BOTH, forcing
`arch.subsystems.length === 0` — no ties with the primary path's own machinery), while the
raw `digest.tiers` list still carries both as `kind: 'subsystem'` tiers. Fallback should
then recover exactly 2 chapters, correctly ordered by a real cross-directory import edge.

**Also deciding, not yet in code:** files/tests with no owning chapter (ownership fails
the longest-prefix match against every chosen chapter root — e.g. a file sitting directly
at the scan root with no subdirectory) get a synthetic trailing chapter, `key: '@misc'`
(mirroring `codetour.ts`'s own `@end` sentinel), rather than being silently dropped. No AC
requires this, but repo-tour's own lessons (`kb/wiki/lessons.md`: "a control that silently
declines is a broken control"; graph/skip counts stated rather than implied) argue hard
against quietly losing files that classification says should become steps.

## Surprises worth flagging now

- **`git log --diff-filter=A --name-only --format=...` does NOT put a blank line between
  commits — it puts the blank line right after each commit's header, before that commit's
  file names.** A state machine that resets "current commit" on every blank line (which
  reads naturally from the phrase "commits are blank-line separated") drops every single
  filename, silently, because the reset fires immediately before the names it should have
  captured. Verified by hand with a throwaway repo before writing the real parser.
  `witness.ts` instead detects a header by shape (`sha\tdate\tsubject`, tab-delimited) and
  treats every other non-blank line as a name belonging to the last header seen. Worth a
  `kb/wiki/lessons.md` entry once this ticket closes — filing it here first so it is not
  lost if the session ends before that step.
- `extract.ts`'s `jsSymbols` marks a class's public METHODS `exported: true` whenever the
  class itself is exported — so a class and its own methods can both be candidates for
  "exported symbols capped at 5 by span," and the class's range fully contains its
  methods' ranges. Selecting both would double-stub the same lines. Plan: sort candidates
  by span descending and skip any whose range overlaps one already chosen — the bigger,
  containing symbol wins and its members are treated as subsumed by that same step. Not
  spec text; a resolution of a case the spec didn't anticipate, taken conservatively.
