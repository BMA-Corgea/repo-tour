## Surprises, for the record

1. **`./repo-tour doctor` does not exist.** The ticket brief's AC5 check names it explicitly,
   and README.md documents it (`./repo-tour doctor  # node, git, parsers, providers`), but
   `src/cli.ts`'s command dispatch has no `doctor` case — only `pr`, `serve`/`app`,
   `providers`, `list`/`open`/`library`, `tour`/`inspect`/`digest`. This predates T-11 (grepped
   the whole file; nothing) and `src/cli.ts` is DO-NOT-TOUCH for this ticket, so it was not
   added. Substituted the closest faithful check instead (see AC5 row above) — the actual
   behaviour AC5 cares about (grammars still resolve with nothing configured; CLI unaffected)
   is fully verified; only the literal named command is missing, and that is pre-existing
   documentation drift, not a T-11 regression. **Whoever eventually builds `doctor` should
   know `grammarsDir()`/`assetsDir()` from `src/assets.ts` are exactly the functions it should
   call to report where it's actually looking.**

2. **The plan's suggested README wording was slightly inaccurate.** Plan step 5 suggested
   "`dist/` is committed-built" as the reason a `file:` dependency works. `dist/` is
   gitignored (confirmed in `.gitignore`), not committed — the real reason is that `dist/`
   already exists **on disk** in a checkout that's been built at least once (which
   `npm install` now does automatically too, via `prepare`, even for a plain local install
   with no arguments). Wrote the accurate version instead; see `4ff6698`.

3. **`kb/CODE-MAP.md` was significantly stale**, unrelated to T-11 — it was missing
   `ask.ts`, `askpanel.ts`, `adjudicate.ts`, `checkpoint.ts`, `delta.ts`, `diff.ts`,
   `narrate.ts`, `notes.ts`, `pr.ts`, `prflow.ts`, `prtour.ts`, `prview.ts` entirely (looks
   like it was last regenerated around T-1/T-2, before several later tickets landed). The
   close-out regeneration step caught all of this up along with `src/assets.ts`. Left as
   caught-up rather than hand-trimmed to a T-11-only diff, since a stale map is strictly
   worse and catching it up is exactly what that close-out step is for.

4. **The write-ahead risk resolved cleanly, no `typesVersions` needed.** The concern was
   whether a *consumer's* `tsc` under `moduleResolution: bundler` would actually see the
   `.d.ts` files through the `exports` map's `types` condition. Tested directly: a throwaway
   consumer project (own `tsconfig.json`, `moduleResolution: bundler`, `strict: true`,
   `skipLibCheck: false`) with `node_modules/repo-tour` symlinked in, importing types and
   values from `repo-tour/digest`, `repo-tour/skins`, `repo-tour/assets`, `repo-tour/types`.
   `tsc --noEmit` passed clean — including a `@ts-expect-error` negative control on
   `digest(123)` that only suppresses correctly if `digest`'s parameter is genuinely typed as
   `string` (an accidental `any` fallback would make `@ts-expect-error` itself an error, for
   being unused). Real types, not `any`, are visible through the map as-is. No fallback added.
