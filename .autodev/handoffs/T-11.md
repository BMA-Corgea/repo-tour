`schema/` does not exist yet either — same reasoning, and `files` entries that don't exist are

`node18` resolution) — the VS Code extension's own tsconfig is the real test, but it does not
exist in this session's reach, so I'm verifying at the level this ticket can reach: does
`node`'s own ESM resolver (not `tsc`) resolve every subpath from a directory outside the repo,
and separately, does a `.d.ts` file actually land on disk at each declared path after
`npm run build`. **If the consumer side later can't see types through the map, the fallback is
a root-level `typesVersions` block** (`{ "*": { "digest": ["dist/digest.d.ts"], ... } }`) —
noting it here now per the write-ahead instruction; will add it only if something concrete
