the actual mechanism AC3 depends on:
1. Removed `scripts.prepare` from `package.json`, `rm -rf dist`, ran `npm pack` ->
   tarball had only 14 entries, **no `dist/` at all**. Confirms `prepare` really is what

2. With `prepare` still removed, ran `npm run build` by hand to leave a "stale but valid"
   `dist/` sitting on disk (exactly the state any local dev/CI checkout that has ever run
   `npm run build` will be in), then ran only the AC3 test:
   `npx vitest run test/consumer.test.ts -t "npm pack builds dist"` -> **still green**, 1/1
   passed, even though `prepare` did not exist in `package.json` at that point.
3. Restored `package.json` from a saved copy (`git diff --stat package.json` afterward showed
   no diff), rebuilt `dist/` with the real `prepare` intact, reran the full suite and
   typecheck to confirm the worktree was left exactly as found: both clean, 127/127 again.

Conclusion: `test/consumer.test.ts`'s AC3 block does not `rm -rf dist` before packing, so it
proves "the tarball's contents get shipped correctly" but does **not** prove "`prepare`
regenerated them this run" — it would give a false green on a regression that silently
dropped the `prepare` script, provided a stale `dist/` happened to already exist on disk
(which it always does after the first local build). This is exactly the "does the test
discriminate" question the review brief asks for, and empirically it does not, for this one
scenario. Classed advisory rather than gating because: the feature itself demonstrably works
(step 1 above proves it from a genuinely clean state), a real git-dependency install (the
actual consumer scenario, and what the refinement notes say this check stands in for) always
starts from a fresh clone with no `dist/` at all (it's gitignored, never in git history), so
the blind spot is specific to re-running this test suite repeatedly on the same already-built
dev machine — not a defect in the shipped mechanism. Recommend a fast follow-up:
`rm -rf(dist)` inside the AC3 `it()` (or a `beforeEach`) before invoking `npm pack`, so the
test controls for the "no manual build" condition its own name claims to prove.
