## Angle 3 — `interpretPlan` purity + fold

Checked: read `src/build/interpret.ts` in full; wrote a from-scratch script (not the shipped
test file) that builds a real digest + `buildPlan` output, deep-freezes it with a recursive
`Object.freeze`, and runs the real, unmodified `interpretPlan` against the frozen object;
cross-checked every fold rule against `src/build/plan.ts`'s `authorOnlyDecision`
(`src/build/plan.ts:287-291`) and `src/build/types.ts`'s `Option`/`Step` shapes.

- **Purity, verified beyond the shipped `toEqual` check.** `interpretPlan` did not throw on a
  deep-frozen input `plan` and the frozen object remained frozen (`Object.isFrozen(plan) ===
  true`) after the call. Every mutation point in the fold uses spread copies
  (`{ ...author, ... }` at `src/build/interpret.ts:109`, `{ ...step, decision: { ...step.
  decision, ... } }` at `src/build/interpret.ts:114-122`), never an in-place assignment.
- **File-head range**: `fileHeadRange`/`rangeOf` (`src/build/interpret.ts:49-51, 62-69`)
  correctly produce `{1, min(loc,120)}` for `file` steps and the symbol's own
  `startLine/endLine` for `symbol` steps; `shape` steps return `null` (skipped) — confirmed by
  reading and by the shipped tests (`test/build.test.ts:1516-1524` for shape,
  `:1589-1598` for the file-head range).
- **Dedup on a same-range collision** (`codeStepsFor`'s `seen` Set,
  `src/build/interpret.ts:79-86`) is logically sound — a file step and its sole symbol
  requesting the identical `stepKey` are deduped to one `CodeStep`/one prompt slot, and the
  fold side (`interpretPlan`'s own `steps.map`, `src/build/interpret.ts:145-150`) recomputes
  each step's range independently and looks the meaning up fresh, so both steps still receive
  it. **This exact path has no dedicated test** (`grep -n "dedup\|collision" test/build.
  test.ts` finds nothing on point) — the handoff's own "Surprises" #5 documents the mechanism
  correctly but not that, in this collision, the meaning both steps receive was generated
  against the FILE step's own title/framing (since that is the `CodeStep` instance that
  actually reaches the prompt), not the symbol step's — a minor cross-contamination in an
  admittedly rare, already-flagged-as-rare case. **Advisory.**
- **Author option**: `taken: true` and `id: 'author'` survive via the `{ ...author, ... }`
  spread (`src/build/interpret.ts:109`); only `consequence` is upgraded to `meaning.summary`.
  Confirmed against `plan.ts:290`'s `authorOnlyDecision` (`id: 'author'`,
  `authorChoice: 'author'`), so `foldMeaning`'s `.find((o) => o.id === step.decision.
  authorChoice)!` always resolves.
- **Alternative ids**: `alt-${i+1}` (`src/build/interpret.ts:110-112`) — unique and stable
  within a step's own option list, `taken: false`. Not capped at 2 (see Angle 2).
- **Uninterpreted steps keep T-12's values exactly**: `interpretPlan`'s map returns the
  literal same `step` reference when no meaning is found (`src/build/interpret.ts:145-150`,
  `return meaning ? foldMeaning(step, meaning) : step;`) — not a copy, the same object,
  confirmed by reading and by the shipped `cachedOnly` test
  (`test/build.test.ts:1541-1560`, asserting `options.length === 1`, `why` byte-equal to the
  docstring text, `whySource: 'docstring'`).
- **`cost` is the real `InterpretCost` from `interpretStops`**, not a re-derived or zeroed
  value (`src/build/interpret.ts:141-143, 152`); `calls` = number of distinct files with at
  least one interpretable, non-cached step (confirmed by the shipped test asserting
  `cost.calls === 2` for a two-file fixture, and by my own live CLI run showing `calls: 0`
  under `--cached-only` against an empty cache).
- **A narrow honesty/provenance edge case in the fold** (not a hallucination — this exact
  fallback is specified by the plan itself, `plans/T-13.md` step 3c: `why = meaning.why ||
  why`): `foldMeaning` (`src/build/interpret.ts:119-120`) sets `whySource: 'interpret'`
  *unconditionally*, even in the case where `meaning.why` is empty/whitespace and `why` falls
  back to the pre-existing docstring/none text. In that narrow case the displayed `why` is NOT
  actually the model's own text, yet it is labeled as if it were. The `SYSTEM` prompt
  explicitly instructs the model to always say *something* for `why`, even an honest "cannot
  be inferred" sentence (`src/interpret.ts:166-167`), so this requires a non-compliant reply
  to trigger, and it is untested either way. Given the ticket's own stated philosophy is
  "never invented, [source] honestly [labeled]," this is worth a record even though it is
  narrow and low-likelihood. **Advisory, not gating** — it is the plan's own designed
  fallback, not an implementer deviation from the plan.

**Gating findings: none.**
